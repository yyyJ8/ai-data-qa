## 0. 分析对象与阅读方法

### 0.1 文件构成

原型是**单个 HTML 文件**，没有构建、没有框架、没有路由、没有任何网络请求。

| 区段 | 行号 | 体量 | 说明 |
|---|---|---|---|
| `<head>` + 内联 Font Awesome | 1–15 | 约 1.29 MB | 第 15 行单行 1.22 MB，是 base64 内嵌的 webfont，与业务无关 |
| 应用样式 | 16–820 | 约 800 行 | CSS 变量体系、组件类名（`.qa-*`、`.mc-*`、`.acct-*`、`.rpt-*`） |
| 应用标记 | 822–1341 | 约 520 行 | 应用骨架、4 个页面容器、15 个弹窗 |
| 应用脚本 | 1343–4447 | 3,105 行 | 229 个函数，全部挂在全局 |
| 尾部弹窗标记 | 4448–4593 | 约 145 行 | 数据源、开场白、常问、反馈等弹窗 |

- 字节数：1,614,546
- 总行数：4,594
- SHA256：`c5bb5c6d6f2dd9daac8a4cd97282ffca75f4eddb29e08e3c1686a686509d1a92`

### 0.2 分析方法

1. **静态提取**：用脚本统计 `function` / `onclick` / `innerHTML` / `getElementById` / `localStorage`，得到"函数—DOM—存储"三张对照表。
2. **引用闭环校验**：把 `getElementById('X')` 与文档中真实存在的 `id="X"` 做差集，定位悬空引用（57 个）。
3. **运行时验证**：用本地静态服务 + 浏览器打开原型，记录控制台异常，并通过脚本触发导航、提问、配置等交互，验证真实行为。
4. **口径对照**：把分散在各处的 mock 数字（KPI、驾驶舱、聊天模板）横向比对，确认口径是否一致。

> 结论前置：**原型的"界面"完成度较高，"能力"完成度接近于零。** 所有业务数字都是前端写死的，AI 回答与服务端无关，大量页面只保留了脚本、没有 DOM。

## 1. 技术形态

- **单文件 SPA**：切换页面靠给 `.page-content` 加/去 `active` 类（`navigateTo`，`:1971`），没有 History API，刷新即回到首屏，无法深链。
- **无构建链路**：没有 npm、没有打包、没有 TypeScript；CSS 与 JS 全部内联。
- **无后端**：全文 0 处 `fetch`，所有"数据"来自三处——模块级常量、`Math.random()` 生成、`localStorage`。
- **渲染方式**：模板字符串 + `innerHTML`（87 处），没有虚拟 DOM，也就没有 diff 与局部更新能力。
- **图表实现**：环图用手写 SVG（`renderDonutChart`，`:1479`），柱状图用 `div` 拼高度（`:2722-2728`），没有引入 ECharts / Chart.js。
- **状态存储**：`localStorage` 6 个键 —— `qaSessions`、`qaFeedbacks`、`appConfig`、`mcModels`、`mcSel0`、`qaSidebarCollapsed`。
- **外部依赖**：仅 Font Awesome（已内联）；`html2canvas` 通过 `import()` 动态加载，但所在函数属死代码（`:3560`）。

### 2.3 首屏形态

- 左侧主侧边栏默认展开，宽 220px；进入对话后会自动 `collapsed`（`:2626`）。
- 内容区默认 `page-ai-qa`，展示欢迎页：`你好 / 我是 AI 问数助手 / 开场白 / 你可以这么问我（3 个快捷问题）`。
- "近 30 天记录"侧栏默认收起，点按钮展开；**实际永远为空**（见诊断 P0-1）。
- 顶部只有品牌、消息铃铛（无逻辑）、头像下拉（个人信息/版本/退出登录，退出= `location.reload()`，`:2164`）。

### 2.4 导航实现要点

`navigateTo(p)`（`:1971`）负责四件事：切页面、切菜单高亮、写面包屑、按页面做局部初始化（`:1983-1991`）。它在 `:4270` 被**二次赋值**打补丁，追加了 `sys-model` 的模型列表初始化和一个全局点击监听（该监听在每次导航时重复注册，构成泄漏，见 P2-3）。

## 3. 模块清单

### 3.1 AI 问数（`page-ai-qa`）

页面由三块组成：左侧会话栏（可收起）、中间对话区（欢迎页 / 对话流 / 日志视图三态）、底部输入栏。

#### 3.1.1 欢迎页与开场白

- 入口：首次进入 `page-ai-qa`、新建对话、清空对话。
- 渲染：`renderGreeting()`（`:4410`）读 `appConfig.greeting / greetingText / greetingQuestions`，控制开场白文案与最多两列排布的快捷问题按钮；`toggleAppConfig('greeting')` 时同步刷新（`:4361`）。
- 配置：`showGreetingConfig()`（`:4363`）→ `greetingConfigModal`，可改文案、增删快捷问题，上限 10 条（`:4395`），保存写 `appConfig`（`:4369`）。
- 结论：**真实可用**，且是原型里少数"配置真正驱动界面"的模块。

#### 3.1.2 会话管理（"近 30 天记录"）

- 数据：`_qaSessions`（`:2227`）首次运行注入 8 条演示会话（每条形如"问题 + 一段固定回答"），之后从 `localStorage.qaSessions` 读取；`saveQaSessions` 截断到 500 条（`:2293`）。
- 能力：新建（`:2341`）、加载（`:2359`）、置顶 / 重命名 / 删除（`:2386-2421`）、右键菜单（`:2315`）、按置顶+时间排序（`:2299`）。
- 标题：首条消息前 20 字自动命名（`:2638`），可手动重命名。
- 结论：**逻辑完整、界面为空**。由于导航阶段的异常（P0-1），`renderQaSidebar` 永远不会被触发，实测列表 0 条而内存中 8 条。

#### 3.1.3 输入区

| 元素 | 行为 |
|---|---|
| 文本框 | Enter 发送、Shift+Enter 换行（`:907`）；输入非空时发送按钮不透明（`:2917`） |
| 发送按钮 | `sendChat()`（`:909`） |
| 快捷提问 | `toggleQuickQ()`（`:906`），打开"常问 / 收藏"面板 |
| 麦克风 | `onclick=""`（`:908`）—— **空实现** |

#### 3.1.4 发送链路

`sendChat()`（`:2608`）依次做：取当前会话（没有则新建）→ 隐藏欢迎页、显示对话流 → 收起主侧边栏 → 追加用户气泡与 4 个消息操作按钮 → 清空输入框 → 消息入会话、按需改名、`saveQaSessions()` → `setTimeout(400ms)` 调 `appendAiReply`。

`appendAiReply()`（`:2672`）→ `genAiReply()`（`:2692`）返回一段固定 HTML，写入 `innerHTML`，随后回填"分析过程"步骤。

> 关键：整条链路**没有模型调用**，`genAiReply` 只用了问题文本做展示，数据部分写死 5 个经营单元。

#### 3.1.5 分析过程（可折叠 5 步）

`renderAaSteps()`（`:2655`）渲染固定 5 步：

1. 选择数据表 & 数据时效（含"数据截止日期 2026-05-31"、业务口径说明）
2. 推理逻辑（把用户问题字符串拼进描述）
3. 执行取数 SQL（一段固定 `SELECT ... FROM 经营目标台账`）
4. 展示取数结果（固定 5 个数字）
5. 执行结束

`toggleAaSteps()`（`:2648`）控制展开/收起，箭头随之变化。**文案、SQL、数字全部硬编码。**

#### 3.1.6 回答卡片（四段式）

`genAiReply` 依次拼出 4 个 `.qa-ai-module`：

| 段 | 内容 | 数据来源 |
|---|---|---|
| ① 数据发现 | 经营单元列表、年度、商业目标合计、商解目标合计 | 固定数组 + `total*0.12` |
| ② 数据表格 | 5 行 × 4 列（单元/年度/商业目标/商解目标） | 同左 |
| ③ 数据统计 | 记录数、平均值、最大/最小值及归属单元 | 对固定数组求值 |
| ④ 数据可视化 | 双色柱状图（商业目标 vs 商解目标）+ 图例 | `div` 高度按比例计算 |

底部是操作区（复制 / 反馈 / 语音播报）与"耗时 0.6s Token:342"统计（`:2730`，硬编码）。

#### 3.1.7 追问（延伸问题）

`followUps` 固定 3 条（`:2700`）：`目标差异是什么？`、`目标如何设定？`、`未来趋势如何？`。点击 `quickAsk(t)`（`:2736`）回填输入框并直接发送。与当前问题无关。

#### 3.1.8 消息操作

| 操作 | 实现 | 真实性 |
|---|---|---|
| 收藏 | `qaToggleFavorite`（`:2498`）写入 `_QQ_DATA.favorite` | 仅内存，刷新丢失 |
| 编辑 | `qaEditMsg`（`:2740`）把气泡换成 textarea + 取消/重发 | 可用 |
| 重新发送 | `qaResend`（`:2771`） | 可用 |
| 重新生成 | `qaRegenerate`（`:2791`） | 重新走同一模板 |
| 复制 | `qaCopyText` / `copyResponse`（`:2797` / `:2808`） | 可用 |

#### 3.1.9 反馈（数据有误）

`showOptimizeModal`（`:2591`）从卡片 `data-question` 取问题 → `submitDataError`（`:2601`）写入 `qaFeedbacks`（`aiReply` 为空串、状态"待处理"）→ toast。进入"回复校对"列表，与人工反馈混在一起。

#### 3.1.10 快捷提问

`_QQ_DATA`（`:2457`）：`recommend` 6 条（未被使用）、`favorite` 空数组、`recent` 固定 2 条。面板两个 tab（`:2479`），"常问"直接展示 `recent` 静态数组，**不统计频次**，因此 `appConfig.hotThreshold` 无实际作用。

#### 3.1.11 数据源选择

- 源清单：`_qaSourceFiles`（`:2249`）8 项，分"台账数据"3 项、"统计报表"5 项，全部默认勾选。
- 渲染：`renderQaFilePicker`（`:2260`）→ `qaFilePickerModal`（`:4492`）。
- 计数：`updateQaSourceCount`（`:2281`）写 `#qaSourceIndicator`。
- 结论：**整条链路不可达** —— 没有按钮调用 `toggleFilePicker`（`:2287`），且 `#qaSourceIndicator` 元素不存在，导致 `navigateTo('ai-qa')` 直接抛异常。选择结果也从未参与回答生成。

#### 3.1.12 日志视图

`qaLogView`（`:923`）含时间/用户筛选、标题搜索、刷新、表格，由 `renderQaLog`（`:2919`）渲染，`switchQaTab('log')`（`:2939`）切换。但页面内**没有任何按钮调用 `switchQaTab('log')`**，只有"返回"按钮调 `switchQaTab('chat')`，因此日志页不可达。

### 3.2 应用配置（`page-sys-app`）

6 张卡片（`:983-1046`），每张含图标、名称、开关、描述：

| 卡片 | 配置键 | 开关是否影响行为 |
|---|---|---|
| 对话开场白 | `greeting` | **是**（`renderGreeting` 消费） |
| 下一步问题建议 | `suggestions` | 否（追问 chips 恒定输出） |
| 文字转语音 | `tts` | 否（播报按钮 `onclick=""`） |
| 语音转文字 | `stt` | 否（麦克风 `onclick=""`） |
| 模型配置 | `modelConfig` | 否（仅作入口显隐装饰，实际仍可点） |
| 常问设置 | `hotRecommend` | 否（"常问"列表是静态数组） |

开关状态写 `appConfig` 并持久化（`:4357`）。"对话开场白""常问设置""模型配置"三张卡片带齿轮按钮，分别打开开场白弹窗、常问阈值弹窗、跳转模型配置页。

### 3.3 模型配置（`page-sys-model`）

- 预置 7 个模型（`:4282-4289`）：GPT-4o、GPT-4o-mini、Claude 3.5 Sonnet、DeepSeek-V3、Qwen2.5-72B、GLM-4-Plus、Moonshot-v1；下拉中另有「-- 选择模型 --」与「── 新增模型 ──」两个特殊项。
- 进入页面时 `loadModelConfig()`（`:4293`）合并预置与本地新增、渲染下拉、恢复 `mcSel0`。
- "保存配置"（`:4309`）：写 `mcSel0` + `alert('模型配置已保存')`。
- "新增模型"：填 BaseURL / APIKey / 模型名 → `mcTestConnection`（`:4324`）用 `setTimeout` 800ms 假装连接成功 → `mcAddModel`（`:4337`）写入 `mcModels`。
- 结论：**纯配置表演**。所选模型从未被任何请求使用（全文 0 处 `fetch`），API Key 明文存 `localStorage`。

### 3.4 回复校对（`page-sys-feedback-user`）

- 列表：`renderFeedbacks`（`:2538`），支持问题关键词、用户关键词、状态三条件筛选，分页可切 5/10/20（`:2561`）。
- 数据：`qaFeedbacks`，首次注入 6 条演示（`:2528-2536`），叠加用户在对话里点的"数据有误"。
- 处理：`showFeedbackRemark`（`:2566`）→ `feedbackRemarkModal`，可看问题与 AI 原回复、填备注、改状态；`saveFeedbackRemark`（`:2577`）持久化并 toast。
- 结论：**原型中完成度最高的 CRUD 模块**，但"校对"仅停留在改状态与备注，没有任何"修正正确答案 → 回灌模型"的闭环。

### 3.5 遗留死模块（有代码、无 DOM / 无入口）

| 模块 | 主要函数 | 现状 |
|---|---|---|
| 经营驾驶舱 | `renderHome`、`renderCockpit`、`renderDimTable`、`renderDonutChart`、`renderIndustryTable`、`renderBarCharts`、`openDimDetail`、`openIndustryDetail` | 依赖的 `ck*` 容器已从 DOM 移除；`renderHome` 无任何调用点 |
| 台账三表 | `initTable`、`initTablePPL`、`initTableGoal`、`initTableCommercial`、`renderTable*`、`refreshData` | 表格容器不存在；`refreshData` 无调用 |
| 通用筛选/排序框架 | `sfInit`、`sfFilterBar`、`sfShowFilter`… （`:1864-1970`） | 仅被死模块调用 |
| 报表 1–5 | `renderRpt1`…`renderRpt5`、`initRpt5AnalysisTexts`、`exportRpt*`（`:3028-3592`） | 报表页容器不存在 |
| 账号 / 角色 / 菜单 / 权限 | `acct*` 约 40 个函数（`:3700-4262`） | 页面与 5 个弹窗标记均已移除 |
| 导入记录 | `showImportLog` / `renderImportLog`（`:2192`） | 弹窗在、入口无 |
| 报表内 AI 助手 | `toggleRptAi` / `sendRptAi` / `clearRptAiChat`（`:2895-2916`） | 无容器 |
| 登录页 | 仅剩 CSS（`.login-page` 等），无标记 | 作业明确不要求登录 |

死代码的规模：229 个函数中约 **40% 没有可达调用链**；57 个 `getElementById` 指向不存在的元素。

## 4. 问数主链路（端到端时序）

```
用户输入问题
   │  Enter / 点击发送 / 点快捷问题 / 点追问 chip
   ▼
sendChat()  :2608
   ├─ 无当前会话 → 新建（title='新对话'）
   ├─ 切视图：隐藏欢迎页、显示对话流、收起主侧栏
   ├─ 追加用户气泡 + 4 个消息操作
   ├─ s.msgs.push(user)、msgCount++、首条消息自动命名
   ├─ renderQaSidebar() + saveQaSessions()   ← 侧栏渲染在此处，但初始加载已因 P0-1 跳过
   └─ setTimeout 400ms ─────────────┐
                                    ▼
                          appendAiReply(question)  :2672
                             ├─ genAiReply()  :2692   ← 固定模板，与问题无关
                             ├─ innerHTML += 整张卡片
                             ├─ s.msgs.push(ai, HTML 字符串)
                             └─ 回填 5 步「分析过程」 :2690
                                    │
                                    ▼
                     卡片渲染完成（发现 / 表格 / 统计 / 图 / 操作 / 追问）
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        ▼                           ▼                           ▼
   点追问 chip                点反馈图标                  点"复制"
   quickAsk() :2736         showOptimizeModal :2591      copyResponse :2808
   → 直接再问一次            → submitDataError :2601      → 写剪贴板
                             → qaFeedbacks + toast
```

**表面上**这条链路具备"提问 → 思考 → 取数 → 出表 → 出图 → 追问"的完整体验；**实际上**中间环节没有一次真实计算或模型调用，出参与出题无关。这是原型最核心的"外壳"。

## 5. 前端数据结构

## 6. 真实现 vs 外壳（判定表）

判定口径：
- **可用**：交互闭环、数据能落、刷新可恢复
- **半成品**：逻辑写了但被阻断，或只做了一半
- **空壳**：有界面/有函数，但输出与输入无关，或输出是常量
- **死代码**：有函数，无 DOM / 无入口 / 无调用

| 功能 | 判定 | 证据 |
|---|---|---|
| 欢迎页 + 开场白配置 | 可用 | `renderGreeting` :4410，配置持久化并实时刷新 |
| 会话新建/加载/改名/置顶/删除 | 半成品 | 逻辑完整 :2341-2421，但列表渲染被导航异常阻断 |
| 会话列表展示 | 半成品 | 实测 0 条 / 内存 8 条（P0-1） |
| 提问发送与消息流 | 可用 | `sendChat` :2608，用户气泡、消息入会话、持久化 |
| AI 回答生成 | **空壳** | `genAiReply` :2692 固定 5 单元 + 固定文案，与问题无关 |
| 分析过程 5 步 | **空壳** | `renderAaSteps` :2655 全部硬编码，SQL 也是常量 |
| 四段式卡片（发现/表/统计/图） | **空壳** | :2703-2728 全部基于同一组常量 |
| 耗时 / Token 统计 | **空壳** | `:2730` 写死 "耗时0.6s Token:342" |
| 追问 chips | **空壳** | `followUps` :2700 固定 3 条 |
| 消息复制 | 可用 | `copyResponse` :2808 |
| 消息编辑 / 重发 / 重新生成 | 可用 | :2740-2796 |
| 消息收藏 | 半成品 | 仅存内存 `_QQ_DATA.favorite`，刷新丢失 |
| 快捷提问面板 | 半成品 | 面板可用，"常问"是静态 2 条，不按频次 |
| 数据源选择 | **死代码** | 弹窗在，无入口；指示器元素缺失 |
| 对话日志 | **死代码** | 视图在，无入口 |
| 应用配置开关 | 半成品 | 6 个开关，仅 `greeting` 生效 |
| 模型配置 | **空壳** | 选项/保存/新增都有，无人消费；测试连接是假成功 |
| 回复校对 | 可用 | 列表/筛选/分页/处理/持久化闭环 :2538-2586 |
| 回复校对 → 模型修正 | 不存在 | 只改状态与备注 |
| 驾驶舱（KPI/环图/行业/柱图） | **死代码** | `renderHome` 无调用，`ck*` 容器不存在 |
| 台账三表 + 筛选排序 | **死代码** | 表格容器不存在，`refreshData` 无调用 |
| 报表 1–5 + 导出 | **死代码** | 容器不存在，导出用未引入的 `XLSX` 思路 |
| 导入/导出 | **空壳** | 全部 `alert` 提示"文件将在后台生成" :3594-3599 |
| 账号/角色/菜单/权限 | **死代码** | 页面与弹窗标记已移除 |
| 登录 | 不存在 | 仅剩 CSS |
| 语音输入/播报 | 空实现 | `onclick=""` :908、:2730 |

统计：可用 5 项、半成品 5 项、空壳 7 项、死代码 6 项、不存在 2 项。

## 7. 可复用到新实现的资产

1. **视觉规范**：CSS 变量（主色 `#2F54EB`、圆角、阴影、字号梯度）、组件类名体系，可作为 React 样式基线。
2. **交互约定**：欢迎页快捷问题 → 对话流 → 四段式卡片 → 追问 chips → 消息操作，这套信息架构就是验收时评委预期的样子。
3. **"分析过程"表达**：折叠 5 步（选表 → 推理 → SQL → 结果 → 结束）是 text2sql 可解释性的好载体，值得保留，但必须换成真实数据。
4. **业务口径**：21 个经营单元、14 个行业、3 条产品线、年度 + 截止日期的时间语义、商业目标/商解目标定义。
5. **配置项清单**：开场白、延伸问题、TTS/STT、常问、模型——即"系统管理"的验收点。
6. **回复校对流程**：用户标记 → 列表 → 备注 → 状态流转，可直接映射为后端表。
