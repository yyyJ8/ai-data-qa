## 3. 建议表结构（SQLite）

### 3.1 维度表

```sql
dim_unit(unit_id PK, unit_name, unit_type, region)
dim_industry(industry_id PK, industry_name, industry_category)
dim_product_line(product_line_id PK, line_name)
dim_product(model_id PK, model_name, product_line_id FK)
dim_customer(customer_id PK, customer_name, industry_id FK)
dim_employee(emp_id PK, emp_name, unit_id FK)
dim_date(date_key PK, year, quarter, month, day)
```

### 3.2 事实表

```sql
-- 年度目标
fact_target(year, unit_id FK, product_line_id FK,
            commercial_target NUMERIC,   -- 商业目标（不含税签约额）
            sol_target NUMERIC)          -- 商解目标（不含税收入）
            -- PK: (year, unit_id, product_line_id)

-- 收入/签约
fact_revenue(month, unit_id FK, industry_id FK, product_line_id FK,
             model_id FK, customer_id FK,
             revenue NUMERIC,            -- 不含税收入
             contract_amount NUMERIC)    -- 签约额（含/不含税需明确）

-- 订单
fact_order(order_id PK, contract_no, unit_id FK, customer_id FK,
           product_line_id FK, sign_date, amount NUMERIC, status)

-- 回款
fact_collection(month, unit_id FK, plan_amount NUMERIC, actual_amount NUMERIC)

-- PPL 项目明细（高风险项目问题依赖）
fact_ppl(project_id PK, contract_no, unit_id FK, industry_id FK,
         product_line_id FK, model_id FK, sales_emp_id FK,
         amount NUMERIC, stage, risk_delivery, risk_payment, risk_overall,
         expected_sign_date)
```

### 3.3 关键索引

- `fact_revenue(year(month), unit_id)`、`(industry_id, month)`、`(product_line_id, model_id)`
- `fact_target(year, unit_id)`
- `fact_ppl(risk_overall)`、`(stage)`

### 4.1 语料与数据的缺口（必须决策）

原型演示语料里有三类问题**没有对应数据结构**：

1. **应收账款账龄** —— 需要 `fact_collection` 之外的回款计划表/账期字段。
2. **区域成本** —— 原型只有收入，没有成本科目。
3. **年度预算执行** —— 原型只有"目标"，没有"预算"。

处理方式二选一：补表（推荐，成本/预算各一张事实表），或在评测语料中剔除这三类问题。**不能保留问句却没有数据**，否则演示必然答非所问。

## 5. 数据量建议

| 表 | 行数量级 | 理由 |
|---|---|---|
| `dim_unit` / `dim_industry` / `dim_product_line` | 21 / 14 / 3 | 与原型一致 |
| `dim_customer` | 100–300 | 支撑"按客户 TopN" |
| `fact_revenue` | 5,000–20,000 | 24 个月 × 21 单元 × 行业/产品组合 |
| `fact_target` | 21 × 3 × 2 年 ≈ 126 | 目标表天然稀疏 |
| `fact_order` | 1,000–3,000 | 支撑月度趋势与订单数 |
| `fact_collection` | 24 × 21 ≈ 504 | 支撑回款率 |
| `fact_ppl` | 300–800 | 支撑风险项目统计 |

原则：**能做出趋势、同环比、TopN、占比四类图形**；数字之间要能勾稽（月合计 = 季合计 = 年合计）。

## 6. 与新实现的约定

1. 所有金额单位统一为**万元**，接口返回时明确字段单位。
2. 所有时间以 `date` 或 `yyyy-mm` 存储，禁止把时间拼进字符串查询。
3. 维度值使用稳定编码（`unit_id`），展示名从维度表取，禁止在事实表里存中文名。
4. 枚举值集中维护（一份 YAML/JSON），后端 schema 提示、前端下拉、评测语料共用。
5. 口径变更必须同步更新本文件与评测集，不允许只改 SQL。
