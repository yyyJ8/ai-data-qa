# 原型问题诊断

> 诊断对象：`Data/index.html`（官方只读原型，未做任何改动）
> 对应作业要求：**问题诊断** —— 找出当前原型中存在的问题或不合理之处。
> 配套文档：[功能分析](./功能分析.md)、[数据字典草稿](./数据字典草稿.md)

## 0. 基线与复现方法

### 0.1 只读基线

| 文件 | 字节数 | SHA256 |
|---|---|---|
| `Data/index.html` | 1,614,546 | `c5bb5c6d6f2dd9daac8a4cd97282ffca75f4eddb29e08e3c1686a686509d1a92` |
| `Data/README.md` | 1,331 | `57e4236420482c511b6dae8671218b5d9be5ed2904fd38d633a123c20315157e` |

### 0.2 复现方式

用任意静态服务器托管 `Data/` 目录后打开（不要用 `file://`，浏览器会拦截 `import()`），然后：

1. 打开控制台，观察首屏异常。
2. 点击左侧「智能问数」，观察是否报错、会话列表是否有内容。
3. 依次提问「2026 年各经营单元收入和完成率是多少？」与「今天天气怎么样？」，对比两次回答。
4. 在输入框提交 `<b>测试</b>`，观察气泡是否被当成 HTML 渲染。

### 0.3 分级定义

| 级别 | 含义 |
|---|---|
| **P0** | 阻断演示或结论错误：功能不可用、输出与输入无关、安全问题 |
| **P1** | 承诺了但没兑现：开关无效、入口缺失、占位实现 |
| **P2** | 工程与体验质量：性能、可维护性、可访问性、一致性 |

## 1. P0：阻断级问题

### P0-1 切到「智能问数」即抛异常，会话列表永远为空

**现象**：首屏左侧"近 30 天记录"为空；点击侧边栏「智能问数」后依旧为空。

**证据链**：

1. `navigateTo('ai-qa')` 在 `:1984` 调用 `updateQaSourceCount()`。
2. `updateQaSourceCount`（`:2281`）执行 `document.getElementById('qaSourceIndicator').textContent = ...`。
3. 全文档不存在 `id="qaSourceIndicator"` 的元素（`renderQaFilePicker` 只有弹窗，没有指示器）。
4. 于是抛 `TypeError: Cannot set properties of null (setting 'textContent')`，`navigateTo` 在此中断，后续的 `initQaSidebar()` / `renderGreeting()` 都不会执行。

**实测**：控制台报上述 TypeError；`_qaSessions.length === 8`（内存有 8 条演示会话），而 `#qaSessionList` 子节点数为 0；手动调用 `renderQaSidebar()` 后变为 8 条，证明是渲染被阻断而非数据缺失。

**影响**：演示必看的"历史会话"始终空白，且每次点菜单都在控制台留一条红色异常。

**修复方向**：补齐指示器元素或对 `getElementById` 判空；会话列表在应用初始化时就渲染一次，不依赖菜单点击。

---

### P0-2 AI 回答与用户问题无关

**现象**：无论问什么，回答都是"北京/上海/浙江/江苏/山东 5 个经营单元的商业目标与商解目标对比"。

**证据**：`genAiReply(q, dt)`（`:2692-2734`）内部：

- `units` 是写死的 5 条（`:2693`）；
- 商用目标合计取 `total`，商解目标恒等于 `total * 0.12`（`:2708`）；
- 追问恒为 3 条固定文案（`:2700`）；
- 参数 `q` 只被拼进 `data-question` 和分析过程描述（`:2702`、`:2659`），不参与任何计算。

**实测**：先后发送「2026 年各经营单元收入和完成率是多少？」与「今天天气怎么样？」，两次生成的卡片 HTML 去掉问题文本后仅相差 36 个字符（即问题字符串本身），四段式内容完全一致。

**影响**：这是 text2sql 产品的核心能力，当前为零。功能演示与 Code Review 都会被直接击穿。

**修复方向**：接入真实 LLM + 数据库，按"意图 → schema 召回 → SQL → 校验 → 执行 → 结果整形"重做，模板只保留版式，不保留数据。

---

### P0-3 "分析过程"与性能统计全部是假数据

**现象**：每张回答卡片的"分析过程"都是同一套 5 步、同一段 SQL；底部固定显示"耗时 0.6s Token:342"。

**证据**：

- `renderAaSteps`（`:2655-2670`）中 5 个 step 的标题与描述是字面量，SQL 为常量 `SELECT 经营单元, 年度, 商业目标, 商解目标 FROM 经营目标台账 WHERE 年度='2026' ORDER BY 商业目标 DESC LIMIT 5`，与问题无关。
- 统计栏 `耗时0.6s Token:342` 在 `:2730` 写死。
- 回答其实由 `setTimeout(..., 400)`（`:2646`）延迟 400ms 后一次性插入，不存在流式输出。

**影响**：把"没有做的事"包装成"已经做了"，属于误导性展示；评审一旦点开分析过程就会看到 SQL 与数据对不上。

**修复方向**：过程数据必须由后端返回（选表、生成 SQL、执行耗时、token 用量），前端只做呈现；无数据时显示"暂无"。

---

### P0-4 没有任何后端调用，模型配置是纯摆设

**现象**：全文件 0 处 `fetch` / `XMLHttpRequest` / `WebSocket`；"模型配置"页选完模型、点保存，只弹一个 alert。

**证据**：

- `saveModelConfig`（`:4309-4314`）仅 `localStorage.setItem('mcSel0', sel.value)` + `alert('模型配置已保存')`。
- `mcTestConnection`（`:4324-4335`）用 `setTimeout(800)` 直接输出"连接成功"，未发起任何请求。
- `mcAddModel`（`:4337-4346`）把 `{baseUrl, apiKey, modelName}` 存进 `localStorage`。
- `mcSel0` 在全文再无读取点（除下一轮渲染下拉），问数链路完全不知道模型存在。

**影响**：

1. 配置项的"有效性"无法验证，"模型可选"是假承诺；
2. 面试要求是 Python 后端 + text2sql，当前完全没有服务端。

**修复方向**：模型配置落到后端（provider/base_url/model/参数），密钥加密存储，问数时由后端按配置调用 LLM；前端只展示掩码。

---

### P0-5 API Key 明文存储于 localStorage

**证据**：`:4343-4344` 直接把用户输入的 `apiKey` 写进 `localStorage.mcModels`，键值可被同源任意脚本、浏览器扩展读取；页面又通过 `innerHTML` 渲染大量用户可控内容（见 P0-6），等于把密钥暴露给 XSS。

**影响**：真实密钥泄露风险；即使只用于演示，也会被 Code Review 直接指出。

**修复方向**：密钥只存服务端，前端接口只返回 `sk-****1234` 形式；保存接口单独鉴权。

---

### P0-6 存储型 XSS：用户输入被直接拼进 innerHTML

**现象**：输入 `<b>测试</b>` 会被渲染成粗体，而不是原样文本。

**证据**：

- `sendChat`（`:2630`）：`c.innerHTML += '<div class="qa-user-bubble">' + m + '</div>'`，`m` 是原始输入。
- 会话标题同样未转义就进入侧边栏（`:2309`）。
- 反馈列表 `renderFeedbacks`（`:2557`）把 `r.question`、`r.user` 直接拼进表格。
- 消息操作按钮的 `onclick` 用 `m.replace(/'/g,"\\'")` 转义，只处理单引号，反斜杠、双引号、换行都能破坏属性。

**实测**：提交 `<img src=x onerror="window.__xss=1"><b id="probe-node">pwn</b>` 后，`document.getElementById('probe-node')` 存在且 `window.__xss === 1` —— 脚本已执行。

**影响**：本地单机演示危害有限，但这是把"用户输入当 HTML"的系统性缺陷，迁移到多人环境就是存储型 XSS。

**修复方向**：React 默认转义即可解决；确需富文本时用白名单 sanitize；后端对入库内容做长度与字符校验。

## 2. P1：承诺了但没兑现

### P1-1 数据源选择整体不可达，且选择结果不参与回答

- 弹窗 `qaFilePickerModal`（`:4492`）与渲染函数 `renderQaFilePicker`（`:2260`）都在，但 `toggleFilePicker`（`:2287`）**全文没有任何调用点**，页面上也没有"选择数据源"按钮。
- `_qaSourceFiles`（`:2249`）的勾选状态不传入 `genAiReply`（它只接收 `q`、`dt`），因此即使能选，也不会影响结果。
- `updateQaSourceCount` 还引用了不存在的 `#qaSourceIndicator`，是 P0-1 的直接原因。

**修复**：把"数据源"作为正式概念实现——后端维护可问答的数据域（表/报表），前端选择后作为请求参数 `sources[]`，参与 schema 召回。

### P1-2 "常问设置"的阈值完全无效

`saveHotConfig`（`:4440-4444`）只把 `hotThreshold` 存进 `appConfig`；"常问"页签展示的是 `_QQ_DATA.recent` 静态 2 条（`:2467`、`:2489`），没有任何频次统计。

**修复**：后端按用户/全局统计提问频次，阈值来自配置；或前端基于本地会话计数。

### P1-3 "下一步问题建议"开关无效

`appConfig.suggestions` 全文无读取点，追问 chips 恒输出（`:2732`）；开关只在应用配置页自己变灰变亮。

**修复**：渲染追问前读取配置；追问内容由后端基于结果维度生成。

### P1-4 文字转语音 / 语音转文字开关无效

麦克风按钮 `onclick=""`（`:908`），播报按钮 `onclick=""`（`:2730`），未使用 Web Speech API 或任何音频接口。两个开关只改 `appConfig`，无消费方。

**说明**：作业把语音列为可选项，但"开关存在却无效"比"没有该功能"更糟——演示时会给人"做了但坏了"的印象。

**修复**：要么真正实现（浏览器 `SpeechSynthesis` / `SpeechRecognition`，或后端 ASR/TTS），要么直接移除开关。

### P1-5 "近 30 天记录"名不副实

侧栏标题写"近 30 天记录"（`:873`），但 `renderQaSidebar`（`:2295`）只按置顶 + 创建时间排序，**没有任何时间过滤**，最多展示全部 500 条。

**修复**：加时间窗过滤，或改文案为"历史会话"。

### P1-6 对话日志与日志详情不可达

`qaLogView`（`:923`）有完整筛选与表格，`switchQaTab('log')`（`:2939`）也写了，但页面内**没有进入日志的按钮**——唯一的 `switchQaTab` 调用是日志页的"返回"（`:927`）。因此 `renderQaLog`、`loadQaDetail` 永远不会执行。

**修复**：补入口，或删视图。

### P1-7 导入 / 导出全部是占位实现

`importLedger` / `exportLedger` / `importGoal` / `exportGoal` / `importPPL` / `exportPPL`（`:3594-3599`）全部只 `alert('…文件将在后台生成后自动下载')`，既没有生成也没有下载；导入只在本地 `importLogData` 里插一条"成功"记录（`:3593`），**伪造成功状态**。

另有文案不符：筛选弹窗按钮写"导出 Excel"（`:1102`、`:1120`），`exportRptTable`（`:3540-3551`）实际导出的却是 CSV。

**修复**：导入走后端解析（openpyxl/pandas）并落库，返回真实行数与失败明细；导出用真实 xlsx（前后端均可生成）。作业要求"导出 Excel"，CSV 不算。

### P1-8 回复校对没有形成修正闭环

`saveFeedbackRemark`（`:2577-2586`）仅改 `status` 与 `remark`；对话内反馈时 `aiReply` 写的是空串（`:2603`），所以校对弹窗显示"（暂无AI回复数据）"（`:2574`）。

没有任何"人工给出正确答案 → 进入评测集/提示词"的路径，所谓"校对"只是工单状态流转。

**修复**：校对项增加"标准答案/SQL"字段；确认后写入 few-shot 库或回归测试集，形成闭环。

### P1-9 会话评价字段有展示、无写入

`userFeedback` / `adminFeedback` 只出现在种子数据（`:2237-2244`）与日志/详情展示中，静态检索全文 **0 处赋值**，用户端也没有"有用/无用"按钮。

**修复**：要么实现评价入口，要么删字段。

### P1-10 日志时间筛选"全部"依赖 NaN 巧合

`renderQaLog`（`:2920-2924`）：

```js
var days = parseInt(document.getElementById('qaLogTime').value);  // 'all' → NaN
if (days !== 'all') { ... }                                       // NaN !== 'all' 恒真
```

`NaN` 与 `'all'` 比较恒为真，`d.setDate(NaN)` 得到 Invalid Date，`new Date(s.createdAt) < Invalid Date` 恒为 false，于是"全部"恰好没有被过滤。逻辑是错的，只是结果碰巧正确，任何一次重构都会把它变成 bug。

**修复**：显式判断 `value === 'all'`，不做 `parseInt`。

### P1-11 用户筛选与用户字段对不上

日志页用户下拉的值是 `admin` / `user`（`:935`），而会话的 `user` 字段是中文"管理员 / 普通用户"（`:2237-2244`）。`renderQaLog` 用 `s.user !== userF` 比较（`:2925`），选择任何用户都会筛出 0 条。

**修复**：统一为 `user_id`，显示名由后端映射。

## 3. P2：工程与体验质量

### P2-1 体积与首屏

- 单文件 1.61 MB，其中约 1.29 MB 是内联的 Font Awesome 字体（`:15`），占 80%，与业务无关。
- 无缓存指纹、无按需加载、无压缩策略；任何一次改样式都是全量重下。
- `exportRptImg` 通过 `import()` 从 CDN 拉 html2canvas（`:3560`），离线环境直接失败。

**修复**：图标改为按需引入的 SVG 组件或子集字体；构建产物按路由拆包并加 hash 缓存。

### P2-2 全局命名空间污染

229 个函数、数十个 `var`/`let` 全局变量；`navigateTo` 甚至被 `const _origNavigateTo = navigateTo` 二次赋值打补丁（`:4270-4280`），补丁之上再打补丁就会静默叠加/覆盖。

**修复**：模块化（ESM），路由/状态/请求分层。

### P2-3 事件监听泄漏

补丁版 `navigateTo` 每次调用都执行一次 `document.addEventListener('click', …)`（`:4275`），且从不移除。导航 N 次后文档上挂 N 个相同监听器。

**修复**：监听一次性注册在应用根部，或使用 `AbortController` 清理。

### P2-4 字符串拼 HTML 的转义不可靠

`m.replace(/'/g, "\\'")`（`:2630`）只处理单引号；反斜杠、换行、`</script>`、双引号都能破坏属性或闭合标签。87 处 `innerHTML` 写入意味着这不会是孤例。

**修复**：React JSX 自动转义；必须拼 HTML 时使用统一 escape 工具并做单元测试。

### P2-5 重复实现与重复数据

`prodData` 在两个函数里各写一遍（`:1481`、`:1539`）；`fmt` / `fmt1` / `pct` / `sumBy` 等工具函数重复定义；多处"经营单元 21 条"列表硬编码（`:1363`、`:1771`、`:1804`）。

**修复**：单一数据源（常量或接口），工具函数集中管理。

### P2-6 没有加载态、空态、错误态

异步全靠固定 `setTimeout` 伪造（400ms 回答、800ms"连接成功"）；无骨架屏、无失败提示、无重试、无取消、无超时。

**修复**：请求状态机（idle/loading/streaming/success/error），流式输出，可中断。

### P2-7 持久化能力弱且不可迁移

`localStorage` 单机单浏览器，约 5 MB；`saveQaSessions` 存的是**渲染后的 HTML 字符串**（`:2293`），体积随对话线性膨胀；超过 500 条静默截断，用户无感知。

**修复**：会话落库（结构化消息，不存 HTML），分页拉取，跨端一致。

### P2-8 时间处理不规范

`toLocaleString()` 依赖系统语言/时区；日志展示用 `createdAt.slice(0,16)` 截 ISO 串（`:2933`）；无时区、无统一格式。

**修复**：后端存 UTC（或带时区的时间戳），前端统一格式化。

### P2-9 可访问性缺失

图标按钮只用 `title` / `data-title`，无 `aria-label`；大量 `div` 绑 `onclick` 当按钮用（不可 Tab 聚焦、不响应回车）；无焦点管理；`--text-hint:#9CA3AF` 用于 12–14px 文本，对比度不足。

**修复**：原生 `button`、语义化标签、可见焦点环、对比度校验。

### P2-10 响应式只是遮羞布

仅 4 条 `@media`（`:602-604`），768px 以下只隐藏侧边栏文字；表格与聊天卡片仍横向溢出；整套 `.login-*` 样式残留但无对应标记。

**修复**：移动端重排（表格转卡片），或明确声明桌面端优先。

### P2-11 无工程化

无构建、无 lint、无测试、无类型；191 处内联事件与 `addEventListener` 混用；无 `package.json`、无 CI。

**修复**：Vite + TypeScript + ESLint + Vitest/Playwright。

### P2-12 死代码占比高

57 个 `getElementById` 指向不存在的元素；229 个函数中约 40% 没有可达调用链；实际能跑通的只有 3 个页面。早期完整版本的驾驶舱、报表 1–5、台账、账号权限全部残留。

**修复**：重写时不做"删代码"，直接按新架构重建；旧代码只作为交互参考。

## 4. 数据可信度问题

| 问题 | 证据 | 影响 |
|---|---|---|
| 同一指标多套数字 | 聊天模板：北京 商业目标 7950 / 商解 1200（`:2693`）；驾驶舱表：北京 target 7950 / income 6200（`:1393`）；商解目标 = 总收入 × 12%（`:2708`） | 同一问题在不同页面给出不同答案 |
| 随机生成业务数据 | `Math.random()` 造台账、PPL、目标（`:1774-1806`）、驾驶舱明细（`:1430-1437`） | 每次刷新数字都变，演示不可复现，无法写断言 |
| 月/季/年不勾稽 | 12 个月收入随机生成后，季度值由月求和（`:1781-1784`），但年度目标另随机（`:1806`） | 交叉校验必然对不上 |
| 口径只有文字没有约束 | "商业目标 = 不含税签约额"仅出现在分析过程文案（`:2658`） | 无法验证计算是否符合口径 |
| 单一口径来源不唯一 | 21 个经营单元在 3 处各自硬编码 | 改一处漏两处 |

**对新实现的要求**：数据由后端单一来源产出，指标定义写进数据字典并在 SQL 层固化，禁止前端 `Math.random()`。

## 5. 与作业硬性要求的差距

| 作业要求 | 原型现状 | 差距（对原型） | 本实现 |
|---|---|---|---|
