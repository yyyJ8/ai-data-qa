# 演示脚本（3 分钟）

> 用途：面试 / 评审时的固定演示路径。按顺序走，每步都标了「说什么」和「预期看到什么」。

## 0. 准备（30 秒，演示前完成）

```powershell
docker compose up -d --build     # 或：后端 uvicorn + 前端 pnpm dev
# 浏览器打开 http://localhost:8000
```

确认：`http://localhost:8000/api/health` 返回 `status: ok`、`configured: true`、`warehouse.tables: 10`。

---

## 1. 智能问数（60 秒）

**说什么**：自然语言提问 → 选表 → 生成 SQL → 执行 → 四段式回答，全程流式。

1. 点击快捷问题「2026年各经营单元收入排名」，或输入：
   > 2026年各经营单元收入排名前五

   **预期**：卡片依次出现「分析过程 → 数据表格 → 柱状图 → 结论」，底部有耗时、tokens、`查看 SQL`。
2. 展开「分析过程」，指出 3 步：选择数据表 / 生成 SQL / 执行查询——都是真实数据，不是模板文案。
3. 点底部「查看 SQL」，对照表格里的数字与 SQL 聚合口径一致。

## 2. 多轮追问（30 秒）

**说什么**：追问不必重复主语，系统会带上会话历史。

4. 直接输入：
   > 那同比呢

   **预期**：SQL 里出现 2025 与 2026 两年数据，结论给出同比变化，且仍然只取前五。
5. 点击回答下方的「继续问」chips（如「各产品线同比如何？」），验证一键追问。

## 3. 数据台账（30 秒）

6. 左侧切到「数据台账」，切表到「收入明细」，搜索框输入 `北京`。
   **预期**：服务端过滤 + 分页，右上「导出 Excel」下载真实 xlsx（用 Excel 打开确认）。

## 4. 系统管理（40 秒）

7. 「应用配置」→ 关掉「展示开场白」→ 保存 → 回问数页，开场白消失；再打开并保存。
8. 「应用配置」→ 模型设置 → 点「测试连接」。
   **预期**：`连接成功 · deepseek-flash · xxxx ms`，说明配置真实作用于链路。
9. 「回复校对」→ 找到一条「待处理」→ 点「处理」→ 填写修正 SQL：
   `SELECT unit_name AS 单元 FROM dim_unit`
   点「写入评测集」。
   **预期**：提示 `已写入评测集：q31（21 行）`，该行变成「已回灌」。

## 5. 收尾（20 秒）

10. 展示 `samples/eval_cases.jsonl` 新增的一行（`tags: ["from_feedback"]`）。
11. 展示终端里 `pytest` 与 `pnpm e2e` 的结果：后端 77 条、端到端 7 条全绿。

## 常见追问的应答口径

| 评委会问 | 回答要点 |
|---|---|
| SQL 怎么保证安全？ | 两层：静态白名单 + SQLite authorizer 只读；强制 LIMIT、超时中断；写操作在授权器层面直接 DENY |
| 模型会不会胡编字段？ | 表目录（catalog）与库结构有测试校验一致；字段错会执行失败并回灌错误重试一次 |
| 准确率多少？ | 30 条评测集：可执行 100%，数值命中 100%（严格列形态 73%）；语料经两轮对齐，已说明口径 |
| 数据哪来的？ | 自建生成器，固定种子可复现；月/季/年勾稽；`python -m app.db.verify` 8 项自检 |
| 为什么不支持语音？ | 作业列为可选；在线识别不稳定，空壳开关比没有更糟，README 已说明 |
| 怎么部署？ | 多阶段 Dockerfile，单端口 8000，容器启动幂等初始化，数据卷 `./storage` |
