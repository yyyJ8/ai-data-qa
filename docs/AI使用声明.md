# AI 使用声明

> 对应作业要求：技术栈不限、开发工具不限、模型不限；本文件说明 AI 在生产过程中的实际分工与验证方式。

---

## 1. 使用的工具

| 环节 | 工具 |
|---|---|
| 代码阅读与检索 | 本地脚本（正则统计函数 / DOM 引用 / 存储调用）+ 全文检索 |
| 运行时验证 | 无头浏览器（Playwright）打开原型，采集控制台异常并触发交互 |
| 文档撰写 | AI 辅助起草，人工逐条核对行号与结论 |
| 版本管理 | Git，按小步提交（详见 README §7.2） |

## 2. 已完成阶段的分工

### 2.1 AI 完成的部分

- 对 `Data/index.html` 做结构化提取：函数清单、`onclick` 清单、`getElementById` 引用与 DOM 定义做差集、`localStorage` 键值清单。
- 在浏览器中复现问题：导航异常、会话列表为空、AI 回答与问题无关、HTML 注入。
- 起草 `docs/功能分析.md`、`docs/原型诊断.md`、`docs/数据字典草稿.md` 与 README 相关章节。

### 2.2 人工确认的部分

- 每条诊断结论均要求落到"文件 + 行号 + 可复现步骤"，无法落地的结论一律删除。
- "真实现 / 半成品 / 空壳 / 死代码"四档判定，由人工抽查复核，尤其是被判定为"空壳"的功能必须确认其数据来源确实为常量。
- 统计类数字（函数数、悬空 id 数、问题条数）以脚本输出为准，不采用模型口算。

## 3. 结论的验证方式

| 结论类型 | 验证手段 |
|---|---|
| 结构类（多少函数、多少页面、多少弹窗） | 正则统计，数字写入文档前二次核对 |
| 引用类（哪个 id 不存在） | `getElementById` 集合与 `id="..."` 集合求差集 |
| 行为类（点菜单报错、回答与问题无关） | 浏览器实测，记录控制台原文与对比结果 |
| 安全类（XSS） | 提交无害探针 `<img onerror>`，确认 `window` 标志被写入 |
| 数据类（口径不一致） | 同一实体在不同模块的数值横向比对 |

## 4. AI 产出的已知限制

1. 原型共 3,105 行脚本，未逐行通读；分析以"结构 + 关键链路 + 运行时验证"为主，可能遗漏低频死代码分支。
2. 行号基于当前 SHA256 基线的文件；`Data/` 只读，因此行号长期有效。
3. 诊断中的"修复方向"是工程建议，不是唯一解；实现阶段可能调整。

## 5. 实现阶段的约定

- AI 可参与编码，但**每一处 AI 生成的代码需人工 review 后提交**，提交信息中注明范围。
- 涉及数据口径、SQL 生成、密钥处理的代码，必须有测试或可复现验证。
- 本条声明随实现推进更新，不做事后补写。
