## 1. 验收目标

三条验收线，缺一不可：

1. **功能演示**：3 分钟内跑完「提问 → 四段式回答 → 追问 → 台账导出 → 改配置生效」。
2. **Code Review**：结构清晰、无死代码、口径可追溯、错误路径有处理。
3. **部署**：干净机器上 `docker compose up -d` 一条命令可用，数据可自动初始化。

量化门槛：

| 指标 | 目标 |
|---|---|
| 评测集 SQL 可执行率 | ≥ 95% |
| 评测集结果正确率 | ≥ 80%（允许口径差异，需注明） |
| 单次问数 P95 端到端 | ≤ 20 s（含 thinking） |
| 危险 SQL 拦截率 | 100%（DROP/DELETE/UPDATE/ATTACH/PRAGMA 等） |
| 会话/反馈持久化 | 重启后不丢 |

## 2. 架构总览

```
浏览器（React SPA，单端口托管）
   │  REST + SSE
   ▼
FastAPI
   ├── 元数据：会话 / 消息 / 反馈 / 配置（SQLite 读写）
   ├── 业务库：销售经管数据（SQLite 只读连接）
   ├── text2sql pipeline
   │    ① 意图与指代解析（多轮上下文）
   │    ② schema 召回（按问题裁剪表/列）
   │    ③ SQL 生成（deepseek-flash，thinking on）
   │    ④ 校验闸门（单语句 / 只读 / 表白名单 / 强制 LIMIT / 超时 / EXPLAIN）
   │    ⑤ 执行与结果整形（类型归一、行列截断）
   │    ⑥ 洞察与图表推荐
   └── LLM 客户端（openai SDK，配置来自库或 .env）
```

两个 SQLite 文件分离：`backend/data/app.db`（可写，元数据）与 `backend/data/warehouse.db`（只读，业务数据）。

> 路径说明：不放在仓库根目录的 `data/`，因为 Windows 文件系统大小写不敏感，会与只读的官方原型目录 `Data/` 冲突。

## 3. 里程碑

总估 **约 9.5 人日**（不含沟通与返工）。顺序原则：**数据先行 → 链路 → 接口 → 界面 → 闭环 → 部署**。

### M0 环境与骨架（0.5 天）

任务：
1. 启动 Docker Desktop（当前守护进程未运行，需先确认 `docker version` 有输出）。
2. `backend/` 建 `.venv`，锁定依赖清单。
3. 目录骨架 + `.env.example` + 配置加载 + `GET /api/health`。
4. `.gitignore` 补充：`data/*.db`、`.venv`、（已有）。

交付：能 `uvicorn app.main:app` 起来并返回 health。
验收：`curl /api/health` → `{"status":"ok"}`；`docker info` 有 Server 段。

### M1 数据层（1.5 天）

任务：
1. `schema.sql`：10 张表（5 维度 + 5 事实）+ 2 个视图，索引与字段注释齐全。
2. `seed.py`：生成可勾稽数据（月合计 = 季合计 = 年合计），固定随机种子，保证可复现。
3. `init_db.py`：幂等建库，容器启动时执行。
4. `samples/eval_cases.jsonl`：30 条「问句 → 标准 SQL → 期望结果」，覆盖排名 / 占比 / 同比 / 筛选 / 明细 / TopN 六类。
5. 数据自检脚本：断言行数、合计、外键完整性。

验收：删库重跑三条命令可从零复现；评测集里每条标准 SQL 都能执行且结果非空。

### M2 text2sql 核心（2 天）

任务：
1. 意图分类：问数 / 闲聊 / 需澄清（无法映射到数据时反问）。
2. schema 召回：按关键词与表描述打分，只喂相关表列，控制 token。
3. Prompt：DDL 摘要 + 口径说明 + 3–5 条 few-shot（取自评测集）。
4. 输出解析：强制 JSON（`sql / explanation / chart / columns`），Pydantic 校验，失败重试一次。
5. 校验闸门：单语句、只读、表白名单、自动补 `LIMIT`、执行超时 5 s、`EXPLAIN QUERY PLAN` 成本预检。
6. 执行与整形：类型归一（金额/百分比/日期）、行数上限 200、列名中文化。
7. 失败路径：SQL 报错 → 带错误信息重试一次 → 仍失败则返回澄清话术，不返回空白。

验收：评测集跑分达标（≥95% / ≥80%）；手工构造 10 条注入语句全部被拦截。

### M3 接口层（1 天）

任务：
1. `POST /api/chat`（SSE）：分片下发 `stage / table / chart / insight / done / error`。
2. `GET /api/sessions`、`GET /api/sessions/{id}`、`PATCH /api/sessions/{id}`、`DELETE /api/sessions/{id}`。
3. `GET/PUT /api/config/model`（密钥打码返回）、`POST /api/config/model/test`（真实连通性）。
4. `GET/PUT /api/config/app`。
5. `GET /api/data/{table}`：服务端分页、筛选、排序；`GET /api/data/{table}/export` → xlsx。
6. `GET/POST/PATCH /api/feedback`。

验收：httpx 集成测试跑通全链路；SSE 事件顺序稳定，前端可重放。

### M4 前端（2.5 天）

任务：
1. 布局与路由：仅 3 个页面（问数 / 应用配置 / 回复校对），删除原型的死入口。
2. 问数页：欢迎页、会话侧栏、消息流、四段式卡片、折叠的分析过程、追问 chips、消息操作。
3. 状态处理：loading、streaming、空结果、SQL 失败、超时、取消。
4. 图表：ECharts 按后端推荐类型渲染（柱/折线/饼/条形）。
5. 配置页与校对页：替换原型中的假交互。

验收：演示脚本全程无控制台报错；断网/超时/错误 SQL 均有可见反馈。

### M5 管理闭环（1 天）

任务：
1. 模型配置入库（base_url / model / 是否 thinking），密钥加密存储，前端只回显掩码。
2. "测试连接"发起真实请求（最小 token）。
3. 应用配置真生效：开场白文案与快捷问题、延伸问题开关、常问阈值。
4. 回复校对：增加"标准答案 / 标准 SQL"字段，确认后写入 few-shot 库，下一轮问数生效。

验收：改模型 → 下一次回答的模型确实变了；关掉延伸问题 → chips 消失；校对一条 → 同类问题回答改善。

### M6 部署与交付（1 天）

任务：
1. 多阶段 Dockerfile：前端构建产物 → 后端镜像，单端口 8000。
2. `docker-compose.yml`：卷挂载 `data/`，启动时静默初始化。
3. 演示脚本（3 分钟，含 5 个必演动作）+ 截图。
4. README 收尾：架构图、启动方式、口径说明、未实现项说明（语音）。
5. 全量回归：评测集 + 集成测试 + 一次冷启动部署。

验收：`docker compose down -v && docker compose up -d` 后 60 s 内可用。

## 4. 关键技术决策（ADR）

| 编号 | 决策 | 理由与代价 |
|---|---|---|
| ADR-1 | 业务库以 `file:...?mode=ro` 只读挂载 | 从连接层杜绝写操作；代价是无法建临时表，需改写复杂 SQL |
| ADR-2 | SQL 校验采用"白名单 + 静态解析"而非黑名单 | 黑名单必漏；代价是要维护允许的表/函数清单 |
| ADR-3 | 会话只存结构化消息（JSON），不存渲染后 HTML | 原型存 HTML 导致体积膨胀与 XSS；代价是前端需重渲染 |
| ADR-4 | 模型配置存库，密钥用对称加密（key 来自环境变量） | 满足"可配置"且不落明文；代价是换机器需重新配 key |
| ADR-5 | 回答用 SSE 分片，不用一次性返回 | thinking 模型首 token 慢，必须给进度反馈 |
| ADR-6 | 前端不引入重型 UI 库，样式沿用原型 CSS 变量 | 保持视觉一致、体积小；代价是组件需自己写 |
| ADR-7 | 语音不实现，删除相关开关 | 避免"能点没用"；README 写明 |
| ADR-8 | 单用户模式，无鉴权 | 作业明确不要求；接口不暴露用户概念 |

## 7. 评测方案

- **语料**：30 条起步，覆盖排名、占比、同比、筛选、明细、TopN；每条含问句、标准 SQL、期望结果哈希。
- **判定**：执行标准 SQL 与模型 SQL，对结果做规范化（列序无关、数值容差 0.01、空值统一）后比较。
- **回归**：每次改 prompt / 加 few-shot / 换模型，跑全量；结果存 `samples/report-{date}.json`。
- **人工抽检**：正确率不达标时，按失败类型归类（选错表、聚合错、过滤错、时间口径错）。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| thinking 模型首 token 慢 | 演示时"卡住" | SSE + 进度条 + 60 s 超时 + 可取消 |
| SQL 幻觉（选错表/字段） | 答非所问 | schema 裁剪 + few-shot + 执行失败重试 + 澄清兜底 |
| 数据不勾稽 | 被追问即露馅 | 生成器约束 + 自检断言，禁止随机值绕过 |
| 时间不足 | 交付不完整 | M1/M2 优先；M5 可降级为只读配置页 |
| Docker 未启动/镜像拉取慢 | 部署演示失败 | M0 提前验证；镜像源配置；离线包备选 |
| 中文路径/编码 | 构建异常 | 项目固定在 `D:\ai-data-qa`；文件统一 UTF-8 |
| 密钥管理 | 泄露 | 存库加密，前端打码，日志脱敏 |
